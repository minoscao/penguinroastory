# 账户与权限

系统不开放自行注册。首次上线前，在 Cloudflare Worker 设置 `AUTH_SETUP_TOKEN` 密钥（至少 32 字节随机值），由店主在首页输入初始化码并设置自己的管理员账户和密码。初始化只允许成功一次；成功后该码不能再创建账户。不要把码放进网址、源码或 Git。

管理员在“账户管理”中新增账户、修改姓名/账户名/联系方式/邮箱、调整角色及权限、启停账户、设置临时密码。临时密码首次登录只能用于修改密码，不能访问业务。管理员无法查看原密码。修改自身密码使用“修改密码”。系统保留至少一位启用的管理员，禁止管理员停用或降级自己。

权限分为订单、烘焙及曲线、发货及签收、豆子及方案、库存入库、客户档案。每项分别授予查看、操作；豆子与客户可单独授予删除。操作和删除自动包含相应查看权限。下单会扣库存，这是订单操作的一部分；库存手工调整及新增批次单独需要库存操作权限。烘焙完成不等于发货完成。

业务 API 每次读取或修改均检查服务器会话与权限。工作流仅返回该业务需要的数据：订单创建可选择客户姓名，未授权客户档案时不返回联系方式/备注；入库人员只获得订单扣库汇总所需字段；发货人员只读取待发货订单与物流。页面隐藏未授权入口，同时禁用未授权操作，直接访问网址和接口也不能越权。

密码使用加盐 scrypt（N=16384,r=8,p=5），数据库只存哈希。会话令牌随机生成，D1 只存其 SHA-256 摘要。线上 Cookie 为 `__Host-`、HttpOnly、Secure、SameSite=Strict，12 小时到期。账户修改、停用、密码重置、更换密码会撤销该账户全部旧会话。重要账户变更记入 `account_audit`（不记密码和令牌）。暂未提供 MFA 或邮件找回；普通员工忘记密码由管理员重置，所有管理员失去访问时由 Cloudflare 账户所有者处理恢复，不提供公开后门。

新增表：accounts、auth_sessions、auth_limits、auth_bootstrap、account_audit。通过 `authDB()` 的幂等建表初始化，与原有业务表分开，不修改历史订单/库存/曲线。账号版本与最后管理员约束由 D1 触发器保护。

## 本地验证

1. `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`。
2. 启动构建版本，使用单独的 `.wrangler/account-audit-*` 数据目录，绑定测试用 AUTH_SETUP_TOKEN。不能绑定远程数据。
3. 设置 TEST_ORIGIN 为本地地址，TEST_SETUP_TOKEN 为上述测试码；运行 `node tests/auth.integration.mjs`。只对全新的隔离测试库运行。测试账户凭据写入忽略目录 `work/auth-test-records.json`。
4. 同一 TEST_ORIGIN 运行 `node tests/api.integration.mjs`，验证管理员登录下的订单、库存、合并烘焙、曲线修正、发货、筛选等。测试凭据禁止用于正式环境。
5. 用 `tests/cleanup-local.py` 清理业务测试确切记录。停止测试服务后，用 `tests/cleanup-auth-local.py <测试目录> <凭据记录文件>` 清理这些确切测试账户。脚本只允许 .wrangler 下专门的 account-audit 测试目录，且要求数据库全部账户均属于该次测试。

测试范围包括匿名拒绝、非法初始化拒绝、临时密码限制、员工跨业务操作拒绝、提权拒绝、权限变更撤销会话、停用/重置/退出、跨站请求拒绝、账户版本冲突、避免管理员自锁及登录限流。
